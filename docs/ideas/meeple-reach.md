# MeepleReach idea brief

## Problem

Tabletop games can place frequently used decks, tokens, tracks, and shared pieces beyond a player's comfortable reach. Existing accessibility reviews explain the issue well, but a designer or host still has to reason about a concrete table layout by hand.

MeepleReach turns a measured layout into an auditable planning problem. It keeps player positions fixed and searches candidate component positions, then produces artifacts a person can inspect rather than a hidden score.

## Audience and first job

- Board-game designers testing a prototype layout.
- Cafes and convention hosts preparing an accessible table.
- Game groups adapting a setup for measured reach preferences.

The first job is deliberately narrow: given one table, fixed player anchors, user-supplied comfortable reach radii, components, interaction frequency, and candidate slots, find the best feasible component placement.

## Novelty boundary

Bounded searches performed on 2026-08-23 found no GitHub repository whose primary function was exact component-placement planning for tabletop reach accessibility. This is evidence for differentiation, not a guarantee that no similar project exists.

MeepleReach is not:

- a seat allocator or group-balancing tool;
- a game-rules implementation;
- an accessibility diagnosis or legal-compliance checker;
- a generic 2D packing solver;
- a UI-only mockup.

## Why it can earn attention

The project has a clear visual before/after story, a socially useful problem, a zero-service local workflow, embeddable output, and a browser demo. Stars cannot be guaranteed; usefulness, examples, documentation, and reliable releases are the controllable inputs.
