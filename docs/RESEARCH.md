# Project research and differentiation

Date: 2026-08-23

## Need evidence

The tabletop accessibility literature describes physical setup as spatially complex and calls out reach, manipulation space, precision, component position, and interaction frequency:

- [Abletop episode on mobility accessibility](https://access-ability.uk/2025/02/26/abletop-episode-2-mobility-accessibility-in-tabletop-gaming/) discusses setup/teardown, reaching and managing components, and standing to see large boards.
- [Meeple Centred Design paper](https://link.springer.com/article/10.1007/s40869-018-0057-8) presents an accessibility heuristic toolkit and notes the lack of one comprehensive evaluation tool.
- [Meeple Like Us toolkit](https://www.meeplelikeus.co.uk/meeple-centred-design-a-heuristic-toolkit-for-evaluating-the-accessibility-of-tabletop-games/) provides physical-accessibility review prompts.

MeepleReach complements those qualitative tools with a small, explicit geometric calculation. It does not replace user testing or expert assessment.

## Bounded novelty search

GitHub repository searches included:

```text
"board game" accessibility
tabletop accessibility

board game accessibility reach planner
tabletop game layout accessibility
board game component reachability
wheelchair tabletop game layout

meeple-reach
```

No result found in those queries had exact tabletop component-to-slot reach planning as its primary function. Search coverage is finite, names and repositories change, and absence in a result set is not proof of global uniqueness.

## Workspace non-duplication check

The local project inventory was also checked. MeepleReach keeps players fixed and assigns physical components. That is materially different from the existing people/group allocator, furniture route geometry, laundry constraint solver, sunlight geometry, bookshelf move planner, USB-C graph, and music page-turn audit projects.

## Popularity thesis

The project has a visual before/after result, a focused accessibility use case, a no-account browser demo, deterministic CLI artifacts, and a contributor-friendly sample format. These choices improve discoverability and usefulness; they do not guarantee stars, traffic, or adoption.
